# Changelog v1.6.0 (unreleased)

> Built on top of 1.5.0, which is still in internal validation. Anything fixed there is brought
> forward into this version.

## 🚀 New Features

### The project name comes from the directory when nobody has decided it
- A project with no `COMPOSE_PROJECT_NAME` in its properties is now known by its directory,
  using the same rule Docker Compose applies. **A project that has the property set is
  unaffected**, which is every project that went through `hm setup` until now.
- This closes a disagreement that was already there: with the property empty, Compose derived a
  name from the directory and the CLI still believed the name was the empty string. The `hm.*`
  labels were written empty, looking up a service's container found nothing, and `hm list` showed
  the environment under Compose's name rather than the CLI's.
- Two copies of the same repository in different directories are now two environments, which is
  what you want when you clone a project to look at a branch. A name recorded in the properties
  is still shared by every clone, because that is an explicit decision.
- From a worktree the name resolves to the main checkout, so a worktree still does not get an
  environment of its own.
- A directory that yields no usable name (`___`, only symbols) is refused with the project exit
  code and an explanation, instead of Compose's *project name must not be empty*.
- `hm setup` records the name **only when it differs from the directory's**. The question and its
  default are unchanged; what changes is what ends up written in a file that is committed and
  travels to every clone.
- Documented in `docs/project-name.md`.

## 🐛 Bug Fixes

### `hm setup` no longer discards a project's other properties
- Saving the project properties rebuilt the file from three keys, so any other property a project
  had —a custom `BIN_DIR`, for instance— disappeared on the next `hm setup`. The file is now
  merged instead of replaced.

## 🔄 Backward Compatibility

- No project changes name. Existing projects have the property set and are resolved exactly as
  before.
- `hm setup` no longer writes `COMPOSE_PROJECT_NAME` when the chosen name matches the directory.
  A script reading that key out of `properties.json` and expecting it to be present will find it
  absent; `hm describe --json` reports the resolved name and is the right source for it.
