# Changelog v1.5.0 (unreleased)

## 🧪 Pre-releases

| Tag | Date | Purpose |
|---|---|---|
| `1.5.0-rc.1` | 2026-08-20 | Internal validation on real projects before cutting the final release |

Try it, and go back if something breaks:

```bash
cd "$(dirname "$(dirname "$(readlink "$(command -v hm)")")")"
git fetch --tags
git checkout 1.5.0-rc.1     # try the candidate
git checkout main           # back to stable
```

> **Careful**: while on a tag the checkout is detached, and `hm update` currently pulls
> the remote default branch instead of refusing, which silently takes you off the
> candidate. Switching by hand as above is safe. A `hm switch` command that handles this
> proprely is the next change.

## 🚀 New Features

### Machine readable output and non-interactive mode
- Informational commands now emit JSON when their output is piped or redirected, and
  readable text on a terminal. `--json` and `--no-json` force either format.
- New envelope for JSON responses, versioned with `schema_version`, so consumers (CI,
  AI agents and the upcoming `describe`/`list`/`doctor` commands) can rely on a stable
  shape.
- New `--yes` flag and `HM_NON_INTERACTIVE=1` variable: no command waits for input.
  Questions with a default use it; questions that cannot be guessed fail with an
  actionable message instead of hanging forever.
- Errors are now written to stderr in both formats.
- New test suite in `tests/`, in pure Bash and with no external dependencies:
  `tests/run.sh`.

### Versions you can move between
- `hm --version` reports the exact reference —tag, commits ahead, commit, branch, whether
  the checkout is detached or has uncommitted changes, and where it is installed— instead of
  rounding to the nearest tag. It said `1.4.5` while eleven commits ahead of it.
- New `hm switch <version|branch>`, with `--list` and `--stable`. It refuses if the
  installation has uncommitted changes to tracked files, and lists them, rather than
  stashing them for you.
- **`hm update` now refuses to run on a pinned installation.** Before, on a tag, it pulled
  the remote's default branch and silently took you off the version you were validating,
  which is what made sharing release candidates unworkable.
- Documented in `docs/switch.md`, together with the branch and tag model.

> Note for anyone testing `1.5.0-rc.1`: the protection above only exists from this version
> on. While running an older one, switch versions with git rather than with `hm update`.

### Help you can read
- `hm --help` groups the 45 commands by purpose —Environment, Magento, Database, Files,
  Tools, AI— instead of listing them alphabetically, and adds a usage line, examples of the
  most common tasks and a footer with the global options.
- Groups and examples are declared in `data/command_descriptions.json`, so a new command
  joins a group by editing data, not code. A command without a group shows up under `Other`.
- **New three-line logo** instead of the eight-line one, with an ASCII fallback for
  terminals without UTF-8, and not printed at all when the output is piped.
- **Fixed**: piping `hm --help` used to send the headings to stderr, so `hm --help > file`
  lost them. All of the help goes to stdout now.
- Still one query for the whole table: `hm --help` measures ~310 ms and stays within its
  performance budget.
- Group headings are bold rather than green, so they no longer read as command names.
  Colour now means "you can type this" (commands and examples) and weight means structure,
  which also keeps the headings readable on a light terminal theme, where a fixed dark blue
  would not be.

### Terminal manners
- **Database passwords are no longer echoed.** `hm transfer-db` asked for the password of a
  remote database with a plain prompt, so it stayed on screen and in the scrollback.
- **`NO_COLOR` is honoured**, along with `TERM=dumb`, `FORCE_COLOR`, `CLICOLOR_FORCE` and a
  new global `--no-color`, with an explicit precedence documented in the README. If you have
  `NO_COLOR` set in your shell you will notice the difference. The text is identical either
  way. The ASCII logo and link colour used to paint themselves with hardcoded escapes,
  ignoring any decision; they now follow the palette.
- **Questions no longer wipe the screen.** `hm setup` cleared the terminal before every
  question, erasing the previous question and its answer. The requirements table now prints
  below the previous one instead of replacing it, so you can see what you changed.

### Faster CLI
- `hm --help` went from **5 660 ms to ~390 ms**, and from **143 `jq` processes to 3**. The
  command listing asked `jq` three questions per command against the same 13 KB file.
- `hm doctor` went from 3 850 ms to ~1 300 ms: the twelve checks run concurrently and are
  read back in a fixed order, so the report is unchanged.
- Docker Compose detection and its version are no longer resolved on every invocation, and
  are cached against the modification time of the docker binary. Validation of the compose
  configuration is cached against the modification time of the compose files.
- Caches live in `~/.hm/cache/`, never inside the project: `config/docker/` is versioned, so
  a cache file there would end up committed. **No project needs a `.gitignore` change.**
- New performance budgets in `tests/performance/`, and `docs/performance.md` explaining the
  criterion: in a Bash CLI the cost is the number of processes spawned.

### Git worktree safety
- Running `hm` from a git worktree now resolves the compose files, the properties and the
  containers against the **main checkout**, and passes `--project-directory` so the bind
  mounts can no longer be repointed at the worktree.
- The commands that recreate or destroy the environment (`start`, `stop`, `restart`,
  `rebuild`, `down`, `setup`, `install`, `create-project`, `docker-stop-all`) are refused
  from a worktree with exit code `6` and a message explaining what would have happened.
  `--force` overrides it for a single invocation.
- Commands that operate on code warn that the containers serve the main checkout's code.
- `HM_PROJECT_DIR` forces the main checkout when git cannot be used.
- Documented in `docs/worktree.md`.

**Why this matters**: until now, `hm start` from a worktree silently recreated the main
environment with the worktree's mounts, and `hm down -v` destroyed it with its database.

### `hm doctor`
- Twelve checks over the machine and the project, each reporting a severity, what it
  found and the exact command that fixes it. Only errors affect the exit code, so
  `hm doctor && hm start` works as a gate.
- The port check names **which project or process is holding each port**, which is the
  most frequent reason an environment refuses to start and something the CLI never said
  before.
- Runs outside a project too, reporting only the global checks.
- Every check runs in its own process with a time limit: one that hangs or crashes is
  reported as a warning and the rest of the diagnosis carries on.
- Documented in `docs/doctor.md`.

### `hm describe` and `hm list`
- `hm describe` reports everything that defines the current project: URLs, Magento
  version and deploy mode, every service with its image, state and ports, paths, mount
  strategy and Xdebug state. It answers with the environment stopped too, which is when
  it is usually needed. Credentials are omitted unless `--with-secrets` is passed.
- `hm list` inventories every environment on the machine, running or not, with its
  status, root directory, derived branch and flags for orphaned environments and for
  environments without metadata. It is the one command that does not need to run inside
  a project.
- Both honour the output contract, so `| jq` just works, and both are documented in
  `docs/describe.md` and `docs/list.md`.

### Environment metadata on every container
- All services now carry `hm.*` labels: project, root directory, worktree, profile,
  Magento version, `hm` version and optional agent. Values are interpolated by Compose at
  `up` time, so the committed `docker-compose.yml` does not change when they do.
- Only stable identity is stamped. The current branch is derived at read time from
  `hm.root`, which also gives orphan detection: an environment whose directory is gone.
- New discovery helpers in `console/helpers/docker.sh`, used from now on to resolve a
  service inside its own project instead of matching container names by substring.
- Documented in `docs/environment-labels.md`.

## 🔄 Backward Compatibility

- **Exit codes are now specific instead of a generic `1`**: `2` invalid arguments,
  `3` Docker unavailable, `4` project not configured, `5` service not running. Scripts
  checking `$? -eq 1` need adjusting; checking for "non-zero" keeps working.
- Interactive use in a terminal is unchanged.
- Commands whose stdout is data (`mysqldump`, `mysql`, passthrough commands) are never
  wrapped in JSON.
- Environments created before this version have no `hm.*` labels. They are still
  discovered through the standard Compose labels and reported as having no metadata;
  `hm setup -f` followed by `hm rebuild` adds them.
