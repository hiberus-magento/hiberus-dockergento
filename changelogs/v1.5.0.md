# Changelog v1.5.0 (unreleased)

## 🚀 New Features

### Machine readable output and non-interactive mode
- Informational commands now emit JSON when their output is piped or redirected, and
  readable text on a terminal. `--json` and `--no-json` force either format.
- New envelope for JSON responses, versioned with `schema_version`, so consumers (CI,
  AI agents and the upcoming `describe`/`list`/`doctor` commands) can rely on a stable
  shape.
- New `--yes` flag and `HM_NON_INTERACTIVE=1` variable: no command waits for input.
  Questions with a default use it; questions that cannot be guessed fail with an
  actionable message instead of hanging forever.
- Errors are now written to stderr in both formats.
- New test suite in `tests/`, in pure Bash and with no external dependencies:
  `tests/run.sh`.

### `hm doctor`
- Twelve checks over the machine and the project, each reporting a severity, what it
  found and the exact command that fixes it. Only errors affect the exit code, so
  `hm doctor && hm start` works as a gate.
- The port check names **which project or process is holding each port**, which is the
  most frequent reason an environment refuses to start and something the CLI never said
  before.
- Runs outside a project too, reporting only the global checks.
- Every check runs in its own process with a time limit: one that hangs or crashes is
  reported as a warning and the rest of the diagnosis carries on.
- Documented in `docs/doctor.md`.

### `hm describe` and `hm list`
- `hm describe` reports everything that defines the current project: URLs, Magento
  version and deploy mode, every service with its image, state and ports, paths, mount
  strategy and Xdebug state. It answers with the environment stopped too, which is when
  it is usually needed. Credentials are omitted unless `--with-secrets` is passed.
- `hm list` inventories every environment on the machine, running or not, with its
  status, root directory, derived branch and flags for orphaned environments and for
  environments without metadata. It is the one command that does not need to run inside
  a project.
- Both honour the output contract, so `| jq` just works, and both are documented in
  `docs/describe.md` and `docs/list.md`.

### Environment metadata on every container
- All services now carry `hm.*` labels: project, root directory, worktree, profile,
  Magento version, `hm` version and optional agent. Values are interpolated by Compose at
  `up` time, so the committed `docker-compose.yml` does not change when they do.
- Only stable identity is stamped. The current branch is derived at read time from
  `hm.root`, which also gives orphan detection: an environment whose directory is gone.
- New discovery helpers in `console/helpers/docker.sh`, used from now on to resolve a
  service inside its own project instead of matching container names by substring.
- Documented in `docs/environment-labels.md`.

## 🔄 Backward Compatibility

- **Exit codes are now specific instead of a generic `1`**: `2` invalid arguments,
  `3` Docker unavailable, `4` project not configured, `5` service not running. Scripts
  checking `$? -eq 1` need adjusting; checking for "non-zero" keeps working.
- Interactive use in a terminal is unchanged.
- Commands whose stdout is data (`mysqldump`, `mysql`, passthrough commands) are never
  wrapped in JSON.
- Environments created before this version have no `hm.*` labels. They are still
  discovered through the standard Compose labels and reported as having no metadata;
  `hm setup -f` followed by `hm rebuild` adds them.
